# Phase 4B: State of Understanding — Behavioral Redesign Proposal

> **Status:** AUDIT & DESIGN ONLY — NO SOURCE CODE MODIFICATIONS  
> **Date:** September 4, 2026  
> **Context:** Behavioral refinement of Phase 4A State of Understanding layer (`1ac63bc`)  
> **Constraint:** Minimal interventions only. Preserves Discora's calm, non-gamified aesthetic. Zero schema or RPC changes required.

---

## 1. Design Principles & Goals

The Phase 4B behavioral audit verified that the State of Understanding successfully establishes Discora's core epistemic loop:
$$\text{Evidence} \rightarrow \text{Understanding} \rightarrow \text{Uncertainty} \rightarrow \text{Investigation / Contribution} \rightarrow \text{Evolving Understanding}$$

The purpose of this redesign is **NOT** to add new structural layers or rework the 3-column epistemic model. Rather, it focuses on eliminating high-friction discontinuities identified during live behavioral testing:

1. **Seamless Investigation-to-Action:** When a user is guided to an unresolved claim by the State of Understanding, the transition into evidence contribution must be immediate and obvious.
2. **Robust Multi-Viewport Typography:** The segmented controls on mobile must communicate category identity and count without text truncation at $375\text{px}$ and $390\text{px}$.
3. **Calm Progressive Disclosure:** Complex formulas (such as Evidence Coverage) should be understandable without desktop-only hover dependencies, avoiding clutter or aggressive modals.
4. **Zero Epistemic Distortion:** UI elements must never equate evidence count with absolute certainty, nor consensus with truth.

## 2. Redesign Specifications by Finding

### 2.1 Redesign 1: Actionable Evidence Transition (`P1-1`)
*Resolves finding P1-1: "Add evidence →" CTA deep-link lacks auto-open intent.*

#### Problem
In the State of Understanding, unresolved claims display an action link:
`Add evidence →` which links to `/discussions/${slug}/claims?highlight=${claim.id}`.
When a user clicks this link, the Claims tab loads and highlights the claim card with a focus ring, but the "Attach Evidence" form/drawer remains closed. A new user is forced to inspect the card interface to locate the subtle icon button for attaching evidence.

#### Redesign Proposal
- Update the deep-link URL generated by State of Understanding for unresolved claims to include an action intent parameter:
  `/discussions/${slug}/claims?highlight=${claim.id}&action=attach-evidence`
- In the Claims tab / Claim Card component:
  When `action === 'attach-evidence'` matches the highlighted claim ID:
  - If authenticated: automatically expand the "Attach Evidence" drawer/form and smoothly scroll it into view.
  - If unauthenticated (guest): automatically highlight the card and display a gentle inline tooltip or drawer prompt: *"Sign in to attach evidence to this claim"*, keeping the intention clear without a jarring full-page redirect.
- Replace the generic CTA label in State of Understanding from `Add evidence →` to `Attach evidence →` to match the exact action nomenclature used in the Claims section.

### 2.2 Redesign 2: Mobile Segmented Control Density & Formatting (`P1-2`)
*Resolves finding P1-2: Segmented control label truncation at $375\text{px}$ and $390\text{px}$.*

#### Problem
On screens below $400\text{px}$ wide, the 3-button segmented control container divides horizontal space into roughly $110\text{px} - 120\text{px}$ per button. With current padding (`px-3 py-1.5`) and font styling, `Unresolved (12)` exceeds the button width, causing CSS ellipsis: `Unresolv...`.

#### Redesign Proposal
Refine the mobile segmented control tabs in [`state-of-understanding.tsx`](file:///d:/Projects/Discora/src/features/discussions/components/state-of-understanding.tsx):
1. **Responsive Tab Labels:**
   - Instead of rendering full text `Unresolved (${count})` on all screen widths:
     - On `< sm` ($< 640\text{px}$): Display the label and count in a compact, stacked or pill format:
       - Tab 1: `Supported` + badge `[1]`
       - Tab 2: `Contested` + badge `[1]`
       - Tab 3: `Unresolved` + badge `[12]`
     - Or use abbreviated label tokens on mobile: `Supported`, `Contested`, `Open` / `Unresolved` with counts placed in a distinct sub-badge.
2. **Padding Optimization:**
   - Adjust mobile button padding from `px-3` to `px-2 py-1` with `text-xs tracking-tight font-medium`.
   - Prevent text clipping with `whitespace-nowrap flex items-center justify-center gap-1`.

### 2.3 Redesign 3: Column Header Spacing & Badge Wrapping at $1024\text{px}$ (`P2-1`)
*Resolves finding P2-1: Column 1 title wraps into 3 lines and collides with contradiction badge.*

#### Problem
At $1024\text{px}$ desktop viewport, the 3-column grid width narrows each column to $\sim 300\text{px}$. In Column 1, `Supported by Current Evidence` wraps to 3 lines, and the secondary label `0 contradictions` sits in an inline flex layout that awkwardly breaks beside the text without visual separation.

#### Redesign Proposal
In [`state-of-understanding.tsx`](file:///d:/Projects/Discora/src/features/discussions/components/state-of-understanding.tsx):
- Restructure the column header into a clear 2-tier vertical hierarchy:
  - Top row: Category title (`Supported`, `Contested`, `Unresolved Front`) with its colored dot indicator and count pill.
  - Sub-row: Muted secondary descriptor (`Supported by verified citations`, `Citations in disagreement`, `Awaiting empirical citations`).
- Move the `0 contradictions` and directional counters into the sub-row or individual claim cards rather than crowding the primary column header.

### 2.4 Redesign 4: Progressive Disclosure for Evidence Coverage on Touch (`P2-2`)
*Resolves finding P2-2: Mobile users cannot access hover tooltip explaining Evidence Coverage.*

#### Problem
On desktop, hovering `14% Evidence Coverage` displays: *"14% of claims have attached sources (2 of 14)"*. On mobile touch devices, hover events do not exist, so a mobile user only sees `14% Evidence Coverage` without knowing whether 14% means source coverage or factual certainty.

#### Redesign Proposal
- Update the Evidence Coverage metric pill in the header bar:
  - Add tap/click toggle support on mobile to reveal a compact popover or expand an inline helper text below the badge:
    `2 of 14 claims have attached sources`
  - Ensure the trigger has proper ARIA attributes (`aria-expanded`, `aria-label="Evidence coverage calculation: 2 of 14 claims have attached sources"`).

---

### 2.5 Redesign 5: Calmer Header Subtitle Phrasing (`P3-1`)
*Resolves finding P3-1: "Deterministic synthesis" is overly clinical.*

#### Problem
The current header subtitle reads:
*"Deterministic synthesis of cited evidence, active disputes, and open inquiry lines across this discussion."*
While accurate for engineers, "deterministic synthesis" sounds jargon-heavy to first-time public participants.

#### Redesign Proposal
Refine the subtitle copy to:
*"Live synthesis of cited evidence, active disputes, and open questions across this discussion."*
This preserves Discora's objective, rigorous tone while making it immediately comprehensible to general readers.

## 3. Epistemic Guardrail Review

All proposed refinements adhere strictly to Discora's epistemic principles:
- **No Consensus as Truth:** Agreement votes remain visually secondary and never affect column placement.
- **No False Proof:** The Supported column retains its fallibilist naming (*"Supported by Current Evidence"*) and clearly states citation counts.
- **No Gamification:** No progress bars or "completion" meters. Evidence Coverage remains an objective fraction ($N/M$), not a gamified completion quest.
