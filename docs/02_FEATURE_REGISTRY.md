# Discora - Feature Registry

Version: 1.0

Status: Living Document

Purpose:

This document contains all planned, proposed, future, experimental, and long-term features for Discora.

Features listed here are not automatically approved for implementation.

Before implementation, features must be evaluated against:

* 00_MASTER_CONTEXT.md
* 01_PRD.md
* Technical feasibility
* User value
* Development cost

---

# 1. Consensus System

Status: Phase 2

Description:

Allow discussions and debates to generate structured consensus points.

Consensus should represent:

* Shared understanding
* Common agreements
* Evidence-supported conclusions

Consensus should not represent:

* Truth
* Majority vote
* Forced agreement

---

## Features

* Consensus Creation

* Consensus Challenges

# Feature Evaluation Rules

Before implementation, every feature must satisfy:

1. Aligns with Discora principles.
2. Improves understanding.
3. Respects freedom of thought.
4. Preserves transparency.
5. Does not create artificial authority.
6. Does not prioritize engagement over understanding.
7. Provides meaningful user value.

If a feature violates these principles, it should be rejected regardless of technical feasibility.
